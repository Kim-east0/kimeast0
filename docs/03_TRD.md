# TRD — 현장별 공정·기성 대시보드

## 한눈에 보기

- **기술:** Next.js(화면과 서버를 한 프로젝트로 만드는 도구) + TypeScript, 자동 검사는 Vitest(계산이 맞는지 자동으로 확인하는 도구). 모두 실습조건에서 정해진 것입니다.
- **구조:** 파일 읽기·검사·계산·CSV는 브라우저에서 합니다. 서버는 AI 호출 한 곳(`/api/ask`)만 맡습니다.
- **AI:** Gemini API, 모델 `gemini-3.8-flash`. 호출은 서버에서만 하고, 키는 `.env.local`에 둡니다.
- **저장:** 서버 저장·데이터베이스 없음. 자료는 브라우저 메모리에만 있어서 새로고침하면 다시 가져옵니다.
- **비용·배포:** 월 0원(무료 구간). GitHub 저장과 Vercel 배포는 사용자가 따로 요청한 뒤에만 진행하며, 이 문서는 방법만 안내합니다.

> 교육용 가상 자료입니다. 단위·계산·검증 기준은 `data/데이터설명.md`, `data/검산표.md`를 따릅니다.

## 1. 사용하는 기술과 고른 이유

| 항목 | 정한 것 | 고른 이유 |
|---|---|---|
| 만드는 도구 | Next.js + TypeScript | 실습조건에서 정함. 화면과 AI 호출용 서버를 한 프로젝트로 만들 수 있음 |
| 화면 방식 | 페이지 4개를 한 앱 안에서 이동 | 4개 페이지가 같은 필터·같은 자료를 써야 하므로 자료를 한곳에 두고 나눠 씀 |
| 자료 보관 | 브라우저 메모리(앱 실행 중에만 유지) | 서버 저장·DB 없음(실습조건). 새로고침 후 유지는 하지 않기로 정함 |
| 파일 읽기 | 브라우저에서 CSV·JSON을 직접 읽음 | 파일을 서버로 보내지 않아 원본이 밖으로 나가지 않음 |
| 계산 | TypeScript 순수 함수(화면과 분리된 계산 코드) | 같은 입력에 같은 결과가 나오고 Vitest로 검산표와 맞는지 확인할 수 있음 |
| 자동 검사 | Vitest | 실습조건에서 정함 |
| AI | Gemini API, `gemini-3.8-flash`, 서버에서만 호출 | 실습조건에서 정함. 서버에서만 호출해야 키가 화면에 노출되지 않음 |
| 차트 | 화면 코드로 직접 그리는 SVG(선·막대 그림 형식) | 선 1개·막대 12개 수준이라 별도 서비스·가입이 필요 없음 (AI 결정) |
| 글꼴·색 | `design/site_engineering_operations_hub/DESIGN.md`의 색 이름·글꼴(Inter, 숫자는 JetBrains Mono, 한글은 시스템 글꼴 대체) | 시안의 분위기를 따름. 글꼴 파일은 앱에 포함해 외부 서비스에 의존하지 않음 (AI 결정) |
| 서비스 가입 | GitHub·Vercel·Gemini 외 없음 | 실습조건 |

### 새로 설치하는 것(라이브러리)

| 목적 | 정한 것 | 고른 이유 |
|---|---|---|
| CSV 읽기·쓰기 | 직접 작성한 작은 코드 | 15개 열·144행이라 라이브러리 없이 가능. 따옴표 안의 쉼표·줄바꿈은 처리해야 하므로 검사 항목에 넣음 (AI 결정) |
| Gemini 호출 | Google 공식 SDK(`@google/genai`) 또는 REST 호출 | 구현할 때 문서를 확인해 하나를 고름. 키는 서버에서만 사용 |
| 시험 | `vitest` | 위 표 참고 |

> 설치할 버전은 구현 때 확인해 `package.json`에 고정합니다. 이 문서에서 임의로 정하지 않습니다.

## 2. 폴더 구조 (AI 결정)

```
site-dashboard/
├─ data/                  원본 자료 (수정하지 않음)
├─ design/                Stitch 시안
├─ docs/                  PRD·FRD·TRD·개발계획·테스트결과
├─ src/
│  ├─ app/                페이지 4개와 AI 호출용 서버(api/ask)
│  ├─ components/         필터 막대, 큰 숫자, 현장 목록, 비교표, 차트 등
│  ├─ lib/
│  │  ├─ parse/           CSV·JSON 읽기, 15개 열 변환
│  │  ├─ validate/        가져오기 검사 (FRD 오류 처리 표)
│  │  ├─ calc/            기성률·공정률·공정차이·상태·당월기성액·추이
│  │  ├─ filter/          월·지역·유형·현장 범위 선택
│  │  ├─ export/          CSV 만들기
│  │  └─ ai/              AI에 보낼 자료 만들기·답변 형식 검사
│  └─ state/              지금 자료와 필터를 한곳에서 관리
├─ tests/                 Vitest 자동 검사
├─ .env.local             Gemini 키 (GitHub에 올리지 않음)
└─ .gitignore
```

근거: 계산·검사·내보내기를 화면과 분리해야 화면 없이도 자동 검사로 정답 숫자를 확인할 수 있습니다.

## 3. 자료가 어디서 어디로 가는지

| 단계 | 어디서 | 어디로 | 무엇이 | 서버를 거치나 |
|---|---|---|---|---|
| ① 파일 고르기 | 사용자 컴퓨터 | 브라우저 | CSV 또는 JSON 파일 | 아니오 |
| ② 검사 | 브라우저(검사 코드) | 브라우저 | 144행 변환, 오류·경고 목록 | 아니오 |
| ③ 반영 | 브라우저(검사 통과한 임시 자료) | 브라우저 메모리(지금 자료) | 144행 전체 교체. 오류·취소 시 지금 자료 유지 | 아니오 |
| ④ 필터·계산 | 지금 자료 + 필터 | 화면 | 선택 범위의 지표·순위·추이 | 아니오 |
| ⑤ CSV 내보내기 | 지금 자료 + 필터 | 사용자 컴퓨터 | 같은 범위의 원본 15열, UTF-8 BOM | 아니오 |
| ⑥ AI 질문 | 브라우저 | 서버 `/api/ask` | 질문, 선택 월 원문 행, 계산된 지표, 필요하면 월별 요약 | 예 |
| ⑦ AI 호출 | 서버 | Gemini API | 위 자료를 정리한 요청 | 예(키는 서버에서만) |
| ⑧ AI 답변 | Gemini → 서버 → 브라우저 | 화면 | 답변, 기준 월·현장·근거 숫자·참고 기록 필드 | 예 |

- 서버는 받은 자료를 저장하지 않고 로그에 남기지 않습니다. 근거: 서버 저장·DB가 없기로 정했기 때문입니다.
- 서버는 질문과 자료를 받아 AI 요청만 만듭니다. 숫자는 브라우저에서 이미 계산한 값을 받으며 AI가 계산하지 않습니다.

## 4. 구조의 약속

| 약속 | 내용 | 근거 |
|---|---|---|
| 자료 한 곳 | "지금 자료"와 필터는 한곳에서만 관리하고 4개 페이지가 함께 읽음 | 숫자·차트·표·CSV·AI가 같은 범위를 따르려고 |
| 교체는 한 번에 | 검사를 통과한 새 자료만 한 번에 바꿈. 일부만 바꾸지 않음 | CSV 후 JSON을 가져와도 144행이 되게(288행 방지) |
| 파생값은 저장하지 않음 | 기성률·공정차이·상태·당월기성액은 보여 줄 때 계산 | 원본에 중복 저장하지 않는다는 규칙 |
| 계산 불가는 값으로 표현 | 첫 달 당월기성액은 `null`로 두고 화면에서 "계산 불가"로 표시 | 0이나 누적값으로 대체하지 않기 위해 |
| 반올림은 마지막에 | 계산 중에는 반올림하지 않고 표시할 때만 소수 첫째 자리 | 9월 전체 공정차이 -2.0pp가 정답이 되도록 |
| 범위가 바뀌면 답변 삭제 | 질문마다 범위 표식(월·지역·유형·현장)을 붙여 두고, 응답이 왔을 때 지금 범위와 다르면 버림 | FRD F19-2 |
| 시안 폭 | PC 브라우저 기준(1280px 이상). 모바일은 만들지 않음 | 실습조건: "PC 브라우저에서 쓰는 웹 앱" |

## 5. 실행 방법

개발 환경: Node.js와 npm이 필요합니다. 이 컴퓨터에는 Node v26.13.0, npm 11.20.0이 설치되어 있습니다.

| 순서 | 할 일 | 명령(터미널) | 확인할 것 |
|---|---|---|---|
| 1 | 프로젝트 만들기 | 구현 단계(EPIC ①)에서 `site-dashboard` 안에 Next.js + TypeScript로 생성 | 기존 `data`·`design`·`docs`는 그대로 |
| 2 | Gemini 키 넣기 | `.env.local` 파일에 `GEMINI_API_KEY=강사가_나눠준_값` 한 줄 | 키는 대화에 적지 않음. `.gitignore`에 `.env.local` 포함 |
| 3 | 개발 서버 실행 | `npm run dev` | 브라우저에서 `http://localhost:3000` 열림. 이미 쓰는 포트면 다른 번호 사용 |
| 4 | 자동 검사 | `npm test` | 계산·검사 테스트 통과 |
| 5 | 화면 확인 | 브라우저에서 `data/현장공정기성.csv` 가져오기 | 9월 기성률 67.2%, 점검 D → I → K |

- 이미 실행 중인 다른 서버는 끄지 않습니다. 포트가 겹치면 다른 번호를 씁니다.
- 키가 없어도 대시보드와 CSV는 동작해야 합니다. AI만 "AI 연결 실패"로 안내합니다.

| 항목 | 정한 것 | 이유 |

| 키 노출 금지 | 대화·화면 코드·GitHub·오류 문구에 키 값을 남기지 않음 | 작업규칙 |
| 보내는 자료 | 질문 + 선택 월 원문 행 + 계산된 지표. 추이 질문이면 월별 요약도. 원문과 계산값을 구분해서 | FRD 6절 |
| 지시문(시스템 프롬프트) | ① 주어진 숫자·기록만 근거로 답함 ② issueSummary는 "기록된 상황", actionPlan은 "계획된 대응"으로 설명 ③ 원인 확정·완료 단정 금지 ④ 실제 준공일·미수금·수금·기상 실측은 "자료 없음" ⑤ 범위 밖 월·현장은 범위를 안내 ⑥ 답변에 기준 월·현장 ID·근거를 붙임 | FRD·데이터설명 |
| 질문 길이·대기 시간 | 500자, 30초 (AI 결정) | FRD 7절 |
| 실패 처리 | 키 없음·한도 초과·시간 초과·응답 형식 오류 모두 "AI 연결 실패" 안내. 대시보드·CSV는 계속 사용 | FRD F21 |
| 모의 응답 | 테스트에서는 가짜 응답으로 형식을 검사하고, 화면에 "모의 응답"이라고 표시. 실제 API 성공으로 기록하지 않음 | 검산표 |
| 호출 한도 | 무료 구간 한도를 넘으면 실패 안내 | 비용 0원 유지 |

## 8. 배포 방법 (사용자가 따로 요청한 뒤에만 진행)

| 단계 | 내용 | 누가 시작하나 |
|---|---|---|
| 로컬 검증 | 구현·자동 검사·화면 확인을 끝내고 결과를 보고한 뒤 멈춤 | AI (EPIC 단위) |
| GitHub 저장 | 비공개 저장소에 올림. 사용자가 저장소 주소를 알려 주고 "이 저장소에 올려 줘"라고 요청한 경우에만 진행. `.env.local`은 올리지 않음 | **사용자 요청 후** |
| Vercel 배포 | GitHub 저장소를 연결하고 `GEMINI_API_KEY` 환경 변수를 넣은 뒤 배포. STEP 11에서 사용자가 직접 진행하며, AI에게 맡기려면 프로젝트·저장소를 정한 별도 요청이 필요함 | **사용자 요청 후** |

- GitHub 저장 요청은 Vercel 배포 요청을 포함하지 않습니다.
- GitHub 변경만으로 자동 배포되는 설정은 사용자 요청 전에는 만들지 않습니다.
- "구현 완료", "확인했어요", "다음으로", "알아서 해 주세요"는 저장·배포 승인으로 보지 않습니다.
- 배포 서버에서도 서버 저장·DB는 없으므로 새로고침하면 파일을 다시 가져와야 합니다.
